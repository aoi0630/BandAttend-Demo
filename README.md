# BandAttend Demo

BandAttend（バンドアテンド）は、吹奏楽部の予定確認、出欠回答、欠席・遅刻申請、承認、連絡、集計を一つにまとめる部活動運営支援Webシステムです。

本リポジトリは、作品紹介・コンテスト審査のために本番システムから分離した公開デモ版です。実在する部員の個人情報や本番データは含みません。

## スマートフォン・PCで利用できます

BandAttendは、ブラウザから利用できるレスポンシブWebシステムです。同じURLをスマートフォン、タブレット、パソコンで開くことができ、端末の画面幅に応じて表示が切り替わります。

- **スマートフォン:** 予定確認、出欠回答、お知らせなど、毎日使う操作を優先
- **パソコン:** 回答率、承認状況、出席傾向、部員別・パート別分析などを詳しく表示
- **インストール不要:** App StoreやGoogle Playを経由せず、URLから利用可能

### ホーム画面へ追加する方法

PWA（Progressive Web App）に対応しているため、ホーム画面へBandAttendのアイコンを追加し、アプリに近い感覚で起動できます。

- **iPhone／iPad:** Safariで開く → 共有ボタン →「ホーム画面に追加」→「追加」
- **Android:** Chromeで開く → 右上メニュー →「ホーム画面に追加」または「アプリをインストール」
- **PC:** ChromeまたはEdgeのアドレスバー付近にインストール表示がある場合は、そこから追加

端末やブラウザの種類によって、表示されるメニュー名が多少異なる場合があります。

## 解決したい課題

実際の部活動では、部員がLINEでパートリーダーへ欠席・遅刻を連絡し、パートリーダーが部長・副部長へ転送しています。練習開始時には部長・副部長が欠席者を口頭で共有します。

この方法では、連絡先が複数に分かれ、転記や再確認が必要になります。欠席情報も一覧や履歴として残らないため、当日の確認、過去の振り返り、出席傾向の把握が難しくなります。

BandAttendでは、予定、申請、承認結果、当日の欠席者、運営分析を一つのシステムへ集約します。

## デモの利用方法

ログイン画面で、確認したい役割を選択してください。デモ版ではIDやパスワードを入力せずに、次の役割の画面を体験できます。

- 一般部員
- パートリーダー
- 部長
- 副部長
- 先生
- 管理者

選択式ログインは作品審査用デモだけの機能です。実際の運用では、部員本人のログインID（学籍番号）とパスワードを使用します。

## おすすめの確認順

1. 一般部員で、ホーム・カレンダー・出欠申請・お知らせを確認
2. パートリーダーで、所属パートの承認待ちと部員別の出席状況を確認
3. 部長または副部長で、全部員の出席情報と運営画面を確認
4. 先生で、先生向けホームとお知らせ送信範囲を確認
5. 管理者で、部員管理・予定管理・運営分析を確認

## 主な機能

### 部員向け

- 今日の予定、練習メモ、本番までの日数をホームに表示
- カレンダーで練習・本番予定を確認
- 出席、欠席、遅刻、早退を回答・申請
- 申請結果や未読のお知らせを確認
- To Do、パート連絡、部員一覧、プロフィールを利用

### 承認・運営向け

- パートリーダーが所属部員の申請を承認
- 部長・副部長がパートリーダー本人の申請を承認
- 部長と副部長はお互いの申請を承認
- 正当・不当の分類、承認履歴、未回答者を確認
- 予定日に承認済みの欠席・遅刻者をまとめて表示

### 管理者向け

- 部員、役職、パート、予定、練習メモを管理
- お知らせの対象範囲と既読状況を管理
- 回答率、出席率、欠席傾向を全体・パート・個人別に分析
- 統計、ランキング、表彰、CSVデータを管理
- スマートフォンでは日常操作、PCでは詳細情報を表示

## 役割ごとの考え方

利用者に不要な情報や操作を表示しないよう、役割によって画面と操作範囲を分けています。部員は自分に必要な予定と申請を中心に利用し、役職者は担当範囲の承認や出席情報を確認します。先生は指導と連絡に必要な画面へ絞り、管理者は全体設定と分析を担当します。

## 承認の流れ

| 申請する人 | 承認する人 |
|---|---|
| 一般部員 | 所属パートのパートリーダー |
| パートリーダー | 部長・副部長 |
| 部長 | 副部長 |
| 副部長 | 部長 |

管理者は、トラブル対応や全体管理のため、すべての申請状況を確認できます。

## デモデータ

デモには、実際の利用状況を想像できるよう、約60人の架空の部員、練習・本番予定、出欠、欠席・遅刻申請、お知らせ、既読状況を収録しています。

`BANDATTEND_DEMO_DATABASE=1`を設定した環境では、API起動時にデモ専用データベースを初期化します。セットアップ時は`scripts/setup_portfolio_demo.py`と各`.env.example`を参照してください。

## 公開デモの安全対策

- 氏名、学籍番号、予定、申請理由はすべて架空データ
- 本番データベースとデモデータベースを分離
- `.env`、認証トークン、本番用接続情報をGitHubへ登録しない
- デモアカウントによる登録・編集・承認・削除をAPI側で制限
- 画面上の表示制限だけに頼らず、サーバー側でも更新を拒否

## デモ版と本番版の違い

| 項目 | 公開デモ版 | 本番版 |
|---|---|---|
| ログイン | 役割を選択して体験 | 学籍番号と個人パスワード |
| データ | 約60人分の架空データ | 実際の部員・予定・出欠情報 |
| 更新操作 | 安全のため制限 | 権限の範囲内で登録・編集・承認可能 |
| データベース | デモ専用 | 本番専用 |

## 審査で確認していただきたいポイント

1. 一般部員と役職者で、ホーム画面と利用可能な機能が変わること
2. 予定確認、出欠申請、承認、当日の欠席者確認が一つにつながること
3. パートリーダー、部長、副部長の承認関係を実際の運営に合わせていること
4. 管理者が全体・パート・個人の状況をPCで詳しく分析できること
5. スマートフォンで日常操作がしやすく、ホーム画面にも追加できること
6. 本番と公開デモを分離し、個人情報と更新操作を保護していること

## 動作環境と注意事項

- 推奨ブラウザ：Safari、Google Chrome、Microsoft Edgeの最新版
- 利用にはインターネット接続が必要です

## ローカルでの確認

環境変数は`.env.example`を参照してください。本番の認証情報を使用せず、必ずデモ専用データベースを用意してください。

```bash
python database/init_db.py
python scripts/setup_portfolio_demo.py
uvicorn api.main:app --reload --port 8000
```

フロントエンドは`frontend`ディレクトリで依存関係を導入し、開発サーバーを起動します。

```bash
cd frontend
pnpm install
pnpm dev
```
